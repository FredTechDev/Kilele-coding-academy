1. **Explain:** *(e.g. State why an `elif` ladder evaluates only until the first True condition).*

## ⏱ Lesson Schedule & Timing Breakdown

### 1. Hook & Warm-Up / "Do Now" (5 Minutes)
- **Activity:** A quick "Spot the Bug" challenge or prediction question projected on the board.
- **Prompt:** *"Look at this code on the screen. What will print when `score = 85`? Discuss with your desk partner."*

### 2. Direct Instruction & Live Demonstration — "I Do" (15 Minutes)
- **Instructor Action:** Open VS Code with an empty file. Live-code the demonstration.
- **Teaching Points:**
  - Introduce the concept using a familiar analogy (e.g., traffic lights or grading marks).
  - Show the syntax: `if`, `elif`, `else`, colons `:`, and 4-space indentation.
  - Run the code in the integrated terminal and show how changing variable values alters execution paths.
  - Intentionally trigger a common beginner mistake (e.g. forgetting a colon) and demonstrate how to read the error message.

### 3. Guided Practice & Class Coding — "We Do" (10 Minutes)
- **Activity:** Code along together. The instructor proposes a problem and asks students to dictate the lines of code.
- **Check for Understanding:** Quick thumbs-up / thumbs-down check on syntax rules.

### 4. Independent or Pair Practice — "You Do" (15 Minutes)
- **Activity:** Students work on Level 1 or Level 2 exercises from `03-practical-exercises/`.
- **Instructor Role:** Circulate through the lab, monitoring screens, observing debugging techniques, and asking probing questions (*"Why did you choose an elif here instead of an if?"*).
- **Early Finishers:** Direct to extension challenges or challenge problems.

### 5. Wrap-Up & Exit Ticket Reflection (5 Minutes)
- **Activity:** Close all editor tabs and ask the Exit Ticket question:
- **Sample Exit Ticket Prompt:**
  > *"Write down in one sentence why the order of conditions matters when using `elif`."*
- Students submit their exit ticket before leaving the computer lab.
